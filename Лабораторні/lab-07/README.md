# Лабораторна робота № 7. Пошук даних у бінарному дереві

[Перелік лабораторних робіт](../README.md)

## Мета роботи

Реалізувати пошук цілого ключа в бінарному дереві пошуку, визначити шлях від кореня до результату та пояснити, як висота дерева впливає на кількість порівнянь. Закріпити роботу з покажчиками, конструктором і деструктором.

## Середовище

Консольний проєкт C++ у Microsoft Visual Studio або іншому середовищі з компілятором C++. [Навчальний приклад](src/lab-07-001.cpp) можна зібрати як окрему програму.

## Теоретичні відомості

У бінарному дереві пошуку всі ключі лівого піддерева менші за ключ поточного вузла, а всі ключі правого — більші. У цій роботі повторний ключ пропускаємо. У довільному бінарному дереві розташування вузлів може не залежати від значень ключів, тому правило вибору однієї гілки потребує саме властивості дерева пошуку.

Почніть із кореня. Якщо шуканий ключ дорівнює ключу вузла, поверніть `true`. Якщо ключ менший, перейдіть ліворуч, інакше — праворуч. На кожному кроці, якщо ключ є в дереві, він залишається в піддереві, яке ще перевіряємо. Досягнення `nullptr` означає, що ключа немає. Це правило працює і для порожнього дерева.

Якщо висота `h` вимірюється кількістю вузлів на найдовшому шляху від кореня до листка, пошук відвідує щонайбільше `h` вузлів. Його час становить `O(h)` для непорожнього дерева, а додаткова пам’ять ітеративного пошуку — `O(1)`. Для збалансованого дерева час у найгіршому випадку становить `O(log n)`, а для дерева у формі ланцюга — `O(n)`.

## Завдання та хід роботи

1. Створіть клас `BinarySearchTree` із закритою структурою `Node` і покажчиком `root`. Вузол містить цілий ключ і два покажчики на нащадків. Конструктор задає `root = nullptr`.
2. Реалізуйте метод `insert(int key)`. Використайте правило вибору гілки й створіть вузол за допомогою `new`, коли дійдете до вільного місця. Якщо ключ уже є, залиште дерево без змін.
3. Напишіть метод `contains(int key)` із циклом `while`. Почніть із кореня, порівняйте ключі й оновлюйте покажчик на поточний вузол. Метод має повертати логічний результат і зберігати стан дерева.
4. Передбачте звільнення пам’яті в деструкторі. Рекурсивно звільніть ліве й праве піддерева, після чого видаліть поточний вузол за допомогою `delete`. У прикладі копіювання об’єкта заборонене, щоб два об’єкти не володіли тими самими вузлами.
5. У `main()` вставте ключі `8, 3, 10, 1, 6, 14, 4, 7, 13` у наведеному порядку. Прочитайте з консолі один цілий ключ і виведіть результат. Якщо рядок порожній або містить щось, крім одного цілого числа, повідомте про помилку.

## Приклад і перевірка результату

Для ключа `7` алгоритм відвідає вузли `8 → 3 → 6 → 7` і виведе `Found.`. Для ключа `5` шлях буде `8 → 3 → 6 → 4 → nullptr`, а результатом — `Not found.`.

| Перевірка | Очікуваний результат |
| --- | --- |
| Пошук кореня `8` | `Found.` після перевірки першого вузла |
| Пошук ключа `13` | `Found.` після переходу в праве піддерево кореня |
| Пошук ключа `5` | `Not found.` |
| Пошук будь-якого ключа до першої вставки | `contains` повертає `false` |
| Дві вставки ключа `8` поспіль у порожнє дерево | У дереві один вузол, пошук повертає `true` |
| Введення `abc`, `8x`, `8 3` або порожнього рядка | `Expected one integer.` |

Для перевірки порожнього дерева викличте `contains` перед циклом вставки. Для перевірки дубліката тимчасово задайте масив `{8, 8}` і простежте в налагоджувачі, що обидва покажчики кореневого вузла залишилися рівними `nullptr`.
